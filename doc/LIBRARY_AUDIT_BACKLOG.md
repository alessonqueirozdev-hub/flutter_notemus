## 1. [HIGH/small] (clefs-meter-barlines) Multi-digit time signatures (12/8, 16, 10/4, etc.) render as nothing
**Current:** bar_element_renderer.dart:200-215 `renderTimeSignature` builds the glyph name as `'timeSig${ts.numerator}'` and `'timeSig${ts.denominator}'`. SMuFL only defines single-digit glyphs timeSig0..timeSig9 (confirmed: glyphnames.json has no `timeSig12`/`timeSig16`). For any numerator or denominator >= 10, `metadata.getCodepoint` returns empty and `_drawGlyph` early-returns (bar_element_renderer.dart:231-232), so the time signature is silently omitted. 12/8 — one of the most common compound meters — draws no glyph at all.
**Desired:** Decompose each of numerator and denominator into individual digits, render the digit glyphs left-to-right, then horizontally center the numerator stack over the denominator stack (per SMuFL/Behind Bars).
**How:** Convert numerator/denominator to their decimal strings, map each char c to glyph `timeSig$c`, sum advance widths to get each stack width, and shift the narrower stack by half the width difference so the two stacks are centered. Reuse `metadata.getGlyphAdvanceWidth`. Also update layout_engine.dart:1025-1027 which currently returns a hardcoded `3.0 * staffSpace` regardless of digit count, so wide signatures get reserved width.

## 2. [HIGH/medium] (accidentals-key) No within-measure accidental persistence — every altered pitch redraws its accidental
**Current:** Pitch.accidentalGlyph (lib/core/pitch.dart:218) returns a glyph purely from the pitch's alter/accidentalType, and NoteRenderer.render unconditionally calls accidentalRenderer.render (lib/src/rendering/renderers/note_renderer.dart:152) whenever accidentalGlyph != null. ChordRenderer does the same. A grep for any per-measure accidental state (priorAccidental/activeAccidental/alterMap/measureAccidental) returns nothing — there is no measure-context resolution anywhere in the rendering or layout pipeline.
**Desired:** Accidentals should follow the standard CMN rule: an accidental is shown only on the first occurrence of an altered pitch (same step+octave) within a measure; subsequent identical notes in the same measure show no accidental; a natural is auto-emitted when a pitch reverts to its key-signature/diatonic value mid-measure; the rule resets at each barline. This is core Behind-Bars/Gould behavior that Verovio and LilyPond apply automatically.
**How:** Add a measure-scoped accidental resolver pass (a small AccidentalContext keyed by step+octave) invoked before rendering each measure, taking the active KeySignature into account. Compute a per-note 'displayAccidental' decision (show / hide / force-natural) rather than deriving it from alter alone. Feed that decision into NoteRenderer/ChordRenderer instead of reading Pitch.accidentalGlyph directly. Reset state on every barline.

## 3. [HIGH/medium] (clefs-meter-barlines) Clef is not repeated at the start of each new system (wrapped staff)
**Current:** layout_engine.dart `_layoutMeasure`/`_layoutMultiVoiceMeasure` filter system elements with `isFirstInSystem || !_isSystemElement(element)` (layout_engine.dart:662 and :822). System elements (Clef/KeySignature/TimeSignature) are only emitted when the measure that physically contains them is the first measure of a system. Since the data model normally carries the clef only in measure 1, every system after the first is laid out and rendered with NO clef at its left edge. staff_renderer.dart keeps a running `currentClef` (staff_renderer.dart:74) used only for note pitch placement — it never injects a clef glyph at system starts.
**Desired:** Every system must begin with the prevailing clef (and prevailing key signature) redrawn at its left edge, as in Gould/Verovio/LilyPond. The first system shows clef+key+time; subsequent systems show clef+key (full size) before the first note, with the time signature shown only when it actually changes.
**How:** In the layout cursor, when starting a measure that is `isFirstMeasureInSystem` but is NOT the first measure of the piece, synthesize a leading Clef (from the running clef state) and KeySignature (running key) and lay them out + reserve width, flagging them as 'system-restatement' so the renderer can draw them. Track running clef/key in the same inheritance pass already used for TimeSignature (layout_engine.dart:355-385). The renderer already handles a Clef/KeySignature PositionedElement, so once they are injected they will draw.

## 4. [MEDIUM/small] (noteheads-stems-beams) Beam thickness and inter-beam spacing are hardcoded and diverge from SMuFL/Bravura engravingDefaults
**Current:** BeamRenderer constructor (lib/src/beaming/beam_renderer.dart:29-31) hardcodes beamThickness = 0.4 * staffSpace and beamGap = 0.60 * staffSpace, with a comment that the SMuFL defaults 'looked too heavy'. The bundled assets/smufl/bravura_metadata.json engravingDefaults specify beamThickness = 0.5 and beamSpacing = 0.25. So beams render ~20% too thin AND the gap between secondary beams is ~2.4x the spec. _calculateLevelOffset (beam_renderer.dart:127) compounds this: each extra beam level is offset by (beamThickness + beamGap) = 1.0 SS instead of the correct beamThickness + beamSpacing = 0.75 SS, so 16th/32nd secondary beams sit too far apart. This is item E4 in PROGRESS.md:124, still open (only V4 grouping was fixed).
**Desired:** Beam (filled) thickness = engravingDefaults.beamThickness (0.5 SS) and the center-to-center distance between adjacent beam levels = beamThickness + beamSpacing (0.5 + 0.25 = 0.75 SS), matching Gould/Behind Bars and Verovio output, read from SMuFL metadata rather than hardcoded.
**How:** In BeamRenderer's constructor, replace the literals with metadata-backed lookups: beamThickness = (metadata beamThickness ?? 0.5) * staffSpace; beamGap = (metadata beamSpacing ?? 0.25) * staffSpace. Verify _calculateLevelOffset uses thickness + spacing for the level step. Regenerate beam goldens (s01, c01) after the change.

## 5. [MEDIUM/small] (spacing-justification) Last/underfull system is justified to full width like a full system
**Current:** _justifyHorizontally (layout_engine.dart:548-597) is called unconditionally for every system (call site :471). The only guard is 'extraSpace>0 && measures.length>1', so any final system with 2+ measures that does not fill the line is stretched edge-to-edge. There is no detection of the last system nor a fill-ratio threshold. Per Behind Bars the final (or any sparsely-filled) system must keep natural spacing, not be diluted across the full measure width.
**Desired:** Do not stretch the last system, and do not stretch any system whose natural width is below a fill threshold (e.g. <60-75% of usable width); leave such systems left-aligned at natural spacing.
**How:** In _justifyHorizontally, skip justification when the system is the maximum key in systemMeasures (last system) OR when usedWidth/usableWidth < fillThreshold. Add the threshold as a constant near measureMinWidth. Golden: a 5-measure score that breaks into 4+1 — assert the lone trailing measure keeps natural width.

## 6. [MEDIUM/small] (spacing-justification) Augmentation dots claim no horizontal space, so dots can overlap the next note
**Current:** _getElementWidthSimple returns only notehead (+accidental) width for a Note (layout_engine.dart:1029-1051) with no allowance for duration.dots. DotRenderer draws the first dot at notePosition.dx + 1.0*staffSpace and each further dot +0.6 SS (dot_renderer.dart:51,54), so a single dot extends to ~1.3 SS and a double dot to ~1.9 SS — well past the ~1.18 SS notehead width the cursor advanced. _calculateRhythmicSpacing adds only 0.2 SS per dot to the FOLLOWING gap (lines 1453-1459), insufficient for even one dot and on the wrong element's accounting. Dotted notes therefore crowd or collide with the next note.
**Desired:** Reserve real width for augmentation dots: ~1.0 SS for the first dot plus ~0.6 SS per additional dot, with extra optical clearance when the dot sits on/adjacent to a staff line.
**How:** In _getElementWidthSimple add note.duration.dots-driven width (e.g. dots>0 ? 1.0 + (dots-1)*0.6 SS) to the Note/Chord branch, and remove the under-sized 0.2 SS/dot patch in _calculateRhythmicSpacing. Source the dot advance from a shared constant with DotRenderer so layout and render agree. PROGRESS.md E5 flags the hardcoded dot metrics.

## 7. [MEDIUM/small] (spacing-justification) Rests are given MORE space (1.15x) on the live path, contradicting Gould's ~0.8x and the project's own preference
**Current:** _calculateRhythmicSpacing multiplies a rest's spacing by 1.15 (layout_engine.dart:1448-1450, 'Pausas tem pouco mais ar'). This widens rests. The documented intent (PROGRESS.md and SpacingPreferences.restSpacingRatio default 0.8, spacing_preferences.dart:66-71,98) is that rests take ~80% of the equivalent note spacing per Gould. The dead engine applies restSpacingRatio at spacing_engine.dart:131-133; the live path uses the opposite multiplier.
**Desired:** Apply a rest spacing ratio < 1 (≈0.8) so rests are slightly tighter than equal-duration notes, matching Gould and the configured restSpacingRatio.
**How:** Replace the 1.15 multiplier with preferences.restSpacingRatio (thread SpacingPreferences into LayoutEngine, which is already stored on _spacingEngine). Golden: a measure of quarter-note then quarter-rest then quarter-note; assert the rest gap is ~0.8x the note gap.

## 8. [MEDIUM/small] (slurs-ties) Slur placement/shape ignores intermediate notes; direction decided from endpoints only
**Current:** slur_renderer.dart:_calculateSlurDirection (367-377) decides above/below from only startNote and endNote: if their stem directions match it goes opposite the stems, otherwise it uses the average staff position of just those two notes. Intermediate notes are never consulted. The arch height in slur_calculator.dart:_calculateBaseHeight/calculateSlur is a pure function of horizontal length (k*sqrt(length)), so a slur over a high peak between two low endpoints gets the same shallow arch as a flat slur.
**Desired:** Direction should reflect the whole slurred group (Gould: place on the side opposite the majority of stems; if stems are mixed, place above; never let the arc cut through interior noteheads). The apex should rise to clear the highest interior note, not just scale with length.
**How:** Pass the interior placements (already gathered via _resolveElementPlacements) into the direction decision and into calculateSlur. For direction, count stem-up vs stem-down across the group and use the extreme interior staff position. For shape, raise the apex so the curve clears the highest (above) / lowest (below) interior notehead Y plus clearance -- this also subsumes the skyline fix for the common single-system case.

## 9. [MEDIUM/small] (slurs-ties) Slur/tie endpoints do not clear articulations between the notehead and the arc
**Current:** slur_renderer.dart:_calculateSlurEndpoint and _calculateTieEndpoints derive the endpoint Y from notehead metrics only (_resolveNoteheadMetrics -> halfHeight + a fixed ~0.15-0.4 SS clearance). Articulations (staccato dot, accent, tenuto, marcato) drawn on the same side as the slur are not accounted for, so the slur can start/end on top of or inside an articulation.
**Desired:** When an articulation sits on the slur side of a notehead, the slur endpoint must be pushed outside it (Behind Bars, p.~108: slurs clear articulations and ornaments).
**How:** In _calculateSlurEndpoint, when note.articulations contains a mark on the chosen side, add that mark's glyph height + a small gap to the clearance before placing the endpoint Y. The articulation set is already on the Note model used by the articulation renderer; reuse its glyph heights from SMuFL metadata.

## 10. [MEDIUM/small] (accidentals-key) Key-signature cancellation naturals are drawn but their width is not reserved
**Current:** renderKeySignature (lib/src/rendering/renderers/bar_element_renderer.dart:78-106) draws previousCount.abs() natural glyphs (plus a 0.5-SS gap) to cancel the prior key. But the width estimator (layout_engine.dart:1017-1023) ignores previousCount entirely: it returns 0.5*staffSpace when count==0 and otherwise only counts the new accidentals. A key change to C major (count==0, previousCount=4) draws 4 naturals into a 0.5-SS slot.
**Desired:** The reserved key-signature width must include the cancellation naturals: previousCount.abs() * spacing (0.8 SS each) + the inter-group gap (0.5 SS) + the new accidentals' width. Otherwise cancellation naturals overlap the following clef/notes or the time signature.
**How:** In layout_engine.dart KeySignature branch, when ks.previousCount != null && != 0, add previousCount.abs() * 0.8 + 0.5 (SS) to the returned width, in addition to the existing new-accidental width (so the count==0 cancellation case no longer early-returns 0.5 SS).

## 11. [MEDIUM/small] (accidentals-key) MusicXML import draws spurious accidentals when <alter> is present but <accidental> is absent
**Current:** _musicXmlPitch (lib/src/parsers/parser_support.dart:1539-1551) sets accidentalType from the <accidental> element but sets alter from <alter> (falling back to the accidental). When a MusicXML note has <alter> (the sounding pitch, e.g. implied by the key signature) but no <accidental> element, accidentalType is null yet alter is non-zero, so Pitch.accidentalGlyph (pitch.dart:222-231) infers a glyph from alter and an accidental is drawn that the source explicitly did NOT notate.
**Desired:** In MusicXML, <alter> is the sounding chromatic alteration and <accidental> is the visible symbol; the visible accidental must be governed by presence of <accidental> (plus key-signature/measure context), not by <alter> alone. A note with <alter>-1 but no <accidental> (e.g. Bb under a Bb-major key signature) must render with no flat.
**How:** Decouple display from sounding alter: keep alter for pitch/MIDI, but only set a display-accidental when the <accidental> element is present (or when the new measure-context resolver decides one is needed). Once the within-measure resolver exists (gap 1), this becomes part of the same display-decision path.

## 12. [MEDIUM/small] (dynamics-artic-ornaments) Chord-level articulations are never rendered
**Current:** chord_renderer.dart renders ornaments (line 354) and the chord dynamic (line 372) but has no articulation handling at all (grep 'articulation' in chord_renderer.dart returns nothing). The model supports them — chord.dart:14 declares `final List<ArticulationType> articulations;`. Notes inside the chord are drawn by internal notehead logic, not via NoteRenderer.render, so per-note articulations are also not applied to chord members.
**Desired:** A staccato/accent/tenuto/marcato attached to a Chord must render once, placed at the outermost notehead on the side opposite the stem (Behind Bars: articulation aligns to the chord's stem-far notehead).
**How:** After the noteCenters/positions are known (chord_renderer.dart ~341-352), call noteRenderer.articulationRenderer.render(canvas, chord.articulations, Offset(chordCenter.dx, stemUp ? lowestNoteY : highestNoteY), stemUp: stemUp). Use positions.first/positions.last to pick the correct outer notehead Y.

## 13. [MEDIUM/small] (dynamics-artic-ornaments) Multiple articulations on one note overlap instead of stacking
**Current:** articulation_renderer.dart:29-50. The loop places each articulation independently at `clearanceSS = _getArticulationClearanceSS(type)` measured from the notehead, with per-type constants (staccato 1.0, tenuto 1.1, accent 1.2, staccatissimo 1.2, marcato 1.3 — articulation_renderer.dart:77-88). There is no cumulative offset, so a note with e.g. staccato+accent draws both ~0.1-0.2 SS apart (overlapping), and ordering is by arbitrary type constant rather than the canonical inside-to-outside stack.
**Desired:** Articulations stack outward from the notehead in canonical order (Behind Bars: staccato/tenuto closest to the head, then accent, then marcato outermost), each separated by ~1 SS, with no overlap regardless of how many are present.
**How:** Sort articulations by a canonical rank (staccato/tenuto < accent < marcato/strong < bowings), then accumulate Y: first glyph at base clearance, each subsequent glyph offset by the previous glyph's drawn height + a fixed gap (~0.5-1.0 SS). Also fold combined pairs (staccato+tenuto → articTenutoStaccatoAbove/Below) before stacking.

## 14. [MEDIUM/small] (dynamics-artic-ornaments) Several articulation types silently render nothing (portato, snap, stopped, open, etc.)
**Current:** articulation_renderer.dart:_getArticulationGlyph maps only staccato/staccatissimo/accent/strongAccent/marcato/tenuto/upBow/downBow/harmonics/pizzicato; everything else hits `_ => null` and is skipped. The enum (note.dart:13-31) also defines portato, legato, snap, thumb, stopped, open, halfStopped — all of which produce no glyph. Additionally staccato is drawn with `augmentationDot` rather than the dedicated direction-aware `articStaccatoAbove`/`articStaccatoBelow` glyphs (both confirmed present in glyphnames.json).
**Desired:** portato → articTenutoStaccatoAbove/Below; snap → pluckedSnapPizzicatoAbove; stopped → brassMuteClosed (or handbells); open → brassMuteOpen/articOpen; halfStopped → brassMuteHalfClosed; thumb → stringsThumbPosition. staccato should use articStaccatoAbove/Below.
**How:** Extend the switch with the SMuFL glyphs above (verify each name in glyphnames.json as done for articStaccato). Make these direction-aware (Above/Below) like the existing entries.

## 15. [MEDIUM/small] (dynamics-artic-ornaments) Hairpins use line segments instead of SMuFL hairpin glyphs and lack niente / dashed support
**Current:** symbol_and_text_renderer.dart:_renderHairpin draws two `canvas.drawLine` strokes forming the wedge with `hairpinThickness` from engravingDefaults. There is no handling of a niente circle (open-end hairpin terminating in a small ◦), no dashed hairpins, and the wedge is purely geometric (acceptable, but the dedicated dynamicCrescendoHairpin/dynamicDiminuendoHairpin/dynamicNiente glyphs in glyphnames.json are unused).
**Desired:** Support a niente terminal circle (dynamicNiente or a drawn ◦ at the closed end) and optionally dashed hairpins; ensure the wedge mouth opening follows Behind Bars (~1–1.5 SS at the wide end for long hairpins, scaling slightly with length).
**How:** Add a `niente` flag to Dynamic; when set, draw a small open circle at the pointed end. Optionally scale `height` (currently fixed 0.5 SS half-opening) with hairpin length so long hairpins open wider. Keep the geometric strokes; the glyphs are optional.

## 16. [MEDIUM/small] (tuplets-rests) Dotted rests render without the augmentation dot
**Current:** RestRenderer.render (rest_renderer.dart:38-121) selects a glyph purely from rest.duration.type and draws it; it never reads rest.duration.dots. Notes and chords do render dots (note_renderer.dart:224, chord_renderer.dart:300 via DotRenderer/_renderDots), so a dotted-quarter rest in 6/8 — extremely common — shows as a plain quarter rest with no dot, misrepresenting the duration.
**Desired:** A rest with N dots must draw N augmentationDot glyphs to the right of the rest glyph, vertically placed in the staff space just above the middle line (Gould p.156: dots for rests sit in the 3rd space regardless of the rest's own vertical extent).
**How:** After drawGlyphWithBBox in RestRenderer.render, if rest.duration.dots > 0 draw augmentationDot glyphs. Reuse DotRenderer's spacing constants (first dot at ~1.0 SS right of the glyph's right edge, subsequent dots +0.6 SS). Fix Y to staffPosition +1 (just above the middle line) rather than the existing note-relative resolveDotStaffPosition. Account for the rest glyph's bbox right edge (metadata.getGlyphBoundingBox(glyphName).bBoxNeX) so the dot clears wider glyphs like restQuarter. Layout width for rests (layout_engine.dart:1054 returns a flat 1.5*staffSpace) should also grow by ~0.6 SS per dot.

## 17. [MEDIUM/small] (clefs-meter-barlines) C-clefs on soprano/mezzo-soprano/baritone lines (and bass-on-3rd-line) draw on the wrong staff line
**Current:** bar_element_renderer.dart:30-53 `renderClef` only special-cases treble (line 2), bass (line 4), alto (yOffset 0) and tenor (line 4); everything else falls into `default: yOffset = 0`, i.e. centered on the middle line. So `ClefType.soprano` (C on line 1), `mezzoSoprano` (C on line 2), `baritone` (C on line 5), `bassThirdLine` (F on line 3 vs default center), and `c8vb` all render at the alto position. The model already exposes the correct line via `Clef.referenceLinePosition` / `referenceLineOffsetSmufl` (clef.dart:143-179, 235-269), but the renderer ignores it.
**Desired:** Each clef should be vertically anchored using its own reference line so soprano/mezzo/alto/tenor/baritone C-clefs and the bass-on-3rd-line clef land on their correct staff lines.
**How:** Replace the hand-written switch with `final yOffset = -clef.referenceLineOffsetSmufl * coordinates.staffSpace;` (sign per the engine's inverted Y) and draw with the glyph centered on that line. This removes the special-casing entirely and covers all enum values, including the ones currently broken.

## 18. [MEDIUM/small] (clefs-meter-barlines) Mid-system / mid-measure clef changes render at full size instead of cue size
**Current:** glyphSize is a single constant `coordinates.staffSpace * 4.0` (staff_renderer.dart:97) passed unchanged to BarElementRenderer; `renderClef` always draws at `glyphSize` (bar_element_renderer.dart:55-62). There is no notion of a 'change' clef. A clef appearing partway through a system (e.g. a cello part switching to tenor clef) is drawn at the same size as the opening clef.
**Desired:** A clef change that is not the first element of a system should be drawn at ~70-75% size (cue/change size), per Behind Bars and Verovio/LilyPond, so it reads as a change rather than a new opening clef.
**How:** Add an `isSizeReduced`/`isCourtesy` flag derived in layout (true when a Clef PositionedElement is not the first system element of its system), thread it to `renderClef`, and multiply the glyph size by ~0.72 when set. The same reduced-size path can serve courtesy clefs drawn at line ends.

## 19. [MEDIUM/small] (clefs-meter-barlines) Key-signature cancellation naturals are drawn but get no reserved width (collide with following notes)
**Current:** bar_element_renderer.dart:78-106 renders natural cancellation signs for `ks.previousCount` plus a gap before the new accidentals. But the layout width for a KeySignature (layout_engine.dart:1017-1023) is computed only from `element.count` and completely ignores `previousCount`. So on a key change that cancels the previous key (e.g. 3 sharps -> 1 flat), the naturals are painted into space the layout never allocated, overlapping the new accidentals and/or the first note.
**Desired:** Reserved width must include the cancellation naturals (`previousCount.abs()` glyphs + inter-glyph spacing + the gap before the new key) so the naturals, the new accidentals, and the first note never collide.
**How:** In the KeySignature branch of `_getElementWidthSimple`, when `element.previousCount != null && != 0`, add `previousCount.abs() * 0.8 * staffSpace + naturalWidth + 0.5 * staffSpace` (mirroring the renderer's per-glyph `spacing = 0.8` and the 0.5 gap at bar_element_renderer.dart:101-105).

## 20. [MEDIUM/small] (clefs-meter-barlines) Free-time (senza misura) signature renders as the literal glyph '0/4'
**Current:** `TimeSignature.free()` sets `numerator: 0, denominator: 4, isFreeTime: true` (time_signature.dart:47-48). `renderTimeSignature` (bar_element_renderer.dart:168-216) never checks `isFreeTime`; it falls through to the generic branch and draws `timeSig0` over `timeSig4`, i.e. a visible '0/4', which is musically wrong.
**Desired:** A free-time signature should render nothing (open meter) or an explicit senza-misura indication, never '0/4'.
**How:** At the top of `renderTimeSignature`, `if (ts.isFreeTime) return;` (or optionally draw a configurable senza-misura mark). Also ensure the layout reserves 0 width for free time in layout_engine.dart:1025.

## 21. [MEDIUM/small] (multivoice-ledger) Middle-line note gets stem UP instead of stem DOWN (default single-voice rule)
**Current:** note_renderer.dart:366 _getStemDirectionByVoice returns `staffPosition <= 0` for the positional (single-voice) rule, so a note sitting ON the middle staff line (staffPosition == 0, e.g. B4 in treble) is rendered stem-UP. The doc comment on lines 348-349 even claims the rule is "stem up if on the middle line or below", encoding the wrong convention.
**Desired:** Per Gould 'Behind Bars' (p.13) and Verovio/LilyPond output, the note exactly on the middle line takes a stem DOWN by default; only notes strictly below the middle line stem up. This is the single most common ambiguous case and a visible deviation on every unbeamed middle-line note.
**How:** Change the final return in _getStemDirectionByVoice (note_renderer.dart:366) from `return staffPosition <= 0;` to `return staffPosition < 0;`. Apply the same fix to ChordRenderer.resolveStemDirection (chord_renderer.dart:92-95), which uses `mostExtremePos > 0` — a single note/chord whose most-extreme note is exactly on the middle line should also resolve to stem-down. Add/adjust a unit test asserting B4 (treble) unbeamed -> stem down.

## 23. [MEDIUM/small] (import-export) Lyrics survive import but are dropped on MusicXML export (no round-trip)

**How:** Carry per-gap compressibleSpace (already produced by _expandWithDurationalGuidance) through to PositionedElement, then in _justifyHorizontally allocate extraSpace by gap_compressible/sum(compressible) instead of positionRatio. Note: PROGRESS.md E12 acknowledges this as a known low/medium gap; it remains unimplemented.

## 69. [LOW/medium] (spacing-justification) Tuplet horizontal width is a flat numElements*2.5 SS, ignoring the internal note durations
**Current:** _getElementWidthSimple Tuplet branch (layout_engine.dart:1101-1107) returns element.elements.length * 2.5 SS regardless of whether the tuplet contains eighths, 16ths, or a mix, and regardless of the tuplet ratio. A 3:2 eighth triplet and a 3:2 of dotted-eighth+16th+eighth get identical width, and inner members are evenly spaced rather than proportional to their displayed durations.
**Desired:** Size a tuplet from the sum of its members' proportional (sqrt-law) spacings scaled by the tuplet ratio, and position inner members proportionally rather than at a constant 2.5 SS pitch.
**How:** Compute the tuplet width by running the same per-member rhythmic spacing used for normal notes over element.elements (using each member's modified duration), instead of the constant. Align with the TupletRenderer's inner-member X so layout and render stay consistent. PROGRESS.md E11 flags this.

## 70. [LOW/medium] (accidentals-key) No cautionary / courtesy / editorial accidental support (model, render, and MusicXML import)
**Current:** A grep for cautionary/courtesy/editorial/parentheses accidentals across lib finds only an unrelated MEI-header 'editorialPrinciples' string (lib/core/mei_header.dart:105). The Pitch model (lib/core/pitch.dart) has no display-control field. The MusicXML pitch parser (_musicXmlPitch, lib/src/parsers/parser_support.dart:1531-1552) reads only <step>/<octave>/<alter>/<accidental> and discards the cautionary="yes", editorial="yes", and parentheses="yes"/bracket attributes on <accidental>.
**Desired:** Support cautionary accidentals (often parenthesized) reminding the player of a pitch in a new measure/octave, and editorial accidentals (bracketed). MusicXML's cautionary/editorial/parentheses/bracket attributes should be imported and rendered with the SMuFL bracket glyphs (accidentalParensLeft/Right, accidentalBracketLeft/Right). This is standard in scholarly and performance editions.
**How:** Add an accidentalDisplay enum or flags to Pitch (e.g. {auto, show, cautionary, editorial, hidden}). Parse the <accidental> element's cautionary/editorial/parentheses attributes in _musicXmlPitch. In AccidentalRenderer, when cautionary/editorial, wrap the accidental glyph with parenthesis/bracket glyphs at the correct horizontal offsets.

## 71. [LOW/medium] (clefs-meter-barlines) Additive meter groups (e.g. 3+2+2 over 8) ignored — rendered as a plain summed numerator
**Current:** The model fully supports additive meters via `TimeSignature.additive(groups:[3,2,2], denominator:8)` storing `additiveGroups` and a summed `numerator` (time_signature.dart:55-65, 87). The renderer never reads `additiveGroups`; `renderTimeSignature` just draws the summed numerator, so (3+2+2)/8 displays as plain '7/8' with no '+' separators.
**Desired:** Additive signatures should render the grouped numerator with '+' separators (e.g. 3+2+2) over the denominator, using `timeSigPlus` between digit groups (glyph exists in SMuFL).
**How:** When `ts.isAdditive`, build the numerator row by laying out each group's digits separated by the `timeSigPlus` glyph, summing advance widths; center the (wide) numerator row over the denominator. This also depends on the multi-digit centering fix and on reserving the correct (larger) width in layout.

## 72. [LOW/medium] (multivoice-ledger) Chord ledger lines are not merged across cluster-shifted (seconded) noteheads
**Current:** In ChordRenderer.render (chord_renderer.dart:283-290) each notehead's ledger line is drawn by _drawLedgerLines centered on that notehead's own x (ledgerCenterX = noteX + noteheadCenterX, where noteX includes clusterOffsets[index]). For a chord containing a second that sits on/above a ledger line (e.g. A5+B5 above the treble staff), the two noteheads are horizontally offset by ~one notehead width, so each draws its own short ledger segment — producing two staggered stubs on the same ledger line instead of one continuous line spanning both noteheads.
**Desired:** A ledger line crossing a cluster (seconded notes) should be a single line wide enough to underlie both the shifted and unshifted noteheads, per standard chord engraving. SMuFL even ships reference widths (legerLine 1.328 / legerLineWide 2.128 in bravura_metadata.json) for this.
**How:** Group chord noteheads by ledger-line staffPosition, then for each ledger position draw ONE line spanning from (min notehead left - extension) to (max notehead right + extension) across all noteheads on that line, rather than per-notehead. Compute the span from the cluster offsets already available in chord_renderer.dart. Add a golden with a seconded chord above/below the staff.
