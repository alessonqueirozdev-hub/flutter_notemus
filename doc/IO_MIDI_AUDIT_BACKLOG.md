# Import/Export + MIDI audit backlog (41 confirmed)

## 1. [HIGH/medium] (musicxml-import) Crescendo/diminuendo wedges (<wedge>) are not imported
**Current:** _parseMusicXmlDirections (parser_support.dart:1365) only handles direction-type children dynamics, words, metronome, segno, coda, rehearsal, and octave-shift. There is no case for <wedge>, so hairpin crescendo/diminuendo spanners are dropped entirely. The model supports them: Dynamic has isHairpin and length (lib/core/dynamic.dart:55-66) and DynamicType has crescendo/diminuendo (parser_support.dart:522-524), but only literal <dynamics> abbreviations and the words 'crescendo'/'diminuendo' ever reach it.
**Desired:** Map <wedge type="crescendo"|"diminuendo"> to Dynamic(type: crescendo/diminuendo, isHairpin: true) on start and close it on type="stop". Hairpins are extremely common in any expressive score.
**How:** Add case 'wedge' in _parseMusicXmlDirections: read getAttribute('type'); on 'crescendo'/'diminuendo' emit a hairpin Dynamic, on 'stop' optionally finalize length. Like octave-shift, this is a spanner so a start/stop pairing pass (or storing the open wedge on the parser) is needed to set length; minimally emit the start marker so the hairpin is not lost.

## 2. [HIGH/medium] (musicxml-export) Exporter silently drops all tuplets and every note inside them
**Current:** In `_buildMeasureXml` (lib/src/parsers/musicxml_parser.dart:209-237) the element loop handles Note, Rest, Chord, Dynamic, TempoMark and MusicText, but has NO `else if (element is Tuplet)` branch. The importer wraps triplet/tuplet content in a `Tuplet` element whose children live in `Tuplet.elements` (lib/core/tuplet.dart:35), so on export the Tuplet object is skipped entirely and all the notes it contains vanish from the output. `_buildNoteXml` also never emits `<time-modification>` or `<notations><tuplet type=...>`.
**Desired:** Iterate `Tuplet.elements`, emitting each child note/rest, and add `<time-modification><actual-notes>N</actual-notes><normal-notes>M</normal-notes></time-modification>` to every note plus `<notations><tuplet type="start"/></notations>` on the first and `type="stop"` on the last, using `Tuplet.actualNotes`/`normalNotes`.
**How:** Add a branch `else if (element is Tuplet) { for each child call _buildNoteXml/_buildRestXml }`. Pass actual/normal counts into `_buildNoteXml` so it can emit `<time-modification>` and the start/stop `<tuplet>` notation. This is the single biggest round-trip data-loss bug: import->export of any triplet produces an empty/short measure.

## 3. [HIGH/medium] (mei-import) <scoreDef>/<staffDef> are never read — clef, key, and meter are lost for virtually all real-world MEI files
**Current:** _MeiImportParser.parse (parser_support.dart:1764) jumps straight from <score> to the first <section>, then _parseMeasure (parser_support.dart:1783) only reads clef/keySig/meterSig that appear as direct children of <staff>. There is no handling of <scoreDef> or <staffDef> anywhere. The model already has lib/core/score_def.dart (ScoreDefinition with clef/keySignature/timeSignature/tempo) created specifically for this, but the parser never instantiates or consults it.
**Desired:** Per MEI 5.0 the conventional place for the initial clef/key/meter (and staff line count) is <scoreDef> and its nested <staffDef> at the start of a <section>, NOT inline in <staff>. Verovio, MuseScore and the MEI sample corpus all encode it this way. The parser should read <scoreDef>/<staffDef> @clef.shape/@clef.line, @key.sig (and child <keySig>), @meter.count/@meter.unit (and child <meterSig>), select the staffDef matching staffIndex (@n), and emit a leading Clef/KeySignature/TimeSignature into the first measure, also tracking scoreDef/staffDef changes between measures (mid-score clef/key/meter changes).
**How:** Before iterating sections, capture the score-level and section-level <scoreDef> and the <staffDef n=staffIndex+1> within it. Add a helper _meiStaffDefDefaults(scoreDef, staffDef) returning List<MusicalElement> (Clef/KeySignature/TimeSignature) reusing _meiClef/_meiKeySignature/_meiTimeSignature but reading BOTH the attribute form (@clef.shape, @clef.line, @key.sig, @meter.count, @meter.unit) and the child-element form (<clef>, <keySig>, <meterSig>). Prepend those to voice(1) of the first measure (and re-emit wherever a new <scoreDef> appears). Without this, a typical MEI import currently produces staves with no clef/key/time at all.

## 4. [HIGH/medium] (mei-import) <beam> and <tuplet> container elements drop ALL their child notes (silent data loss)
**Current:** _parseMeiLayer (parser_support.dart:1935-2046) switches only on direct children named note/rest/chord/dynam/tempo/dir/breath/caesura/repeatMark/barLine. There is no case for <beam> or <tuplet>. _meiTupletInfo (parser_support.dart:2290) does check element.name.local == 'tuplet', but it is only ever called on note/rest/chord elements, so that branch is dead — a <tuplet>...</tuplet> container is never visited and its children are never reached. Beam/tuplet are otherwise only read as note attributes (@beam, @tuplet), which is the rarer MEI encoding.
**Desired:** MEI 5.0 almost always encodes beams and tuplets as CONTAINER elements: <beam><note/><note/></beam> and <tuplet num="3" numbase="2"><note/>...</tuplet> (this is what Verovio/MuseScore export). The parser must recurse into these containers. For <beam>, emit the contained notes with BeamType.start on the first, inner on the middle, end on the last. For <tuplet>, wrap children with startTuplet(actualNotes=@num, normalNotes=@numbase)/finishTuplet().
**How:** In _parseMeiLayer add case 'beam': and case 'tuplet': that iterate child.children and dispatch each note/rest/chord through the same logic. Extract the per-element handling into a helper _appendMeiLayerChild(child, accumulator, voiceNumber, currentTimeSignature) and call it from the new container cases (recursively, since beams and tuplets nest). For <tuplet> use accumulator.startTuplet/finishTuplet with @num/@numbase; for <beam> assign BeamType across the contained notes. This is the most damaging gap after scoreDef: any beamed or tupleted passage in standard MEI currently imports as empty.

## 5. [HIGH/large] (musicxml-import) Only one part imported; multi-part/multi-staff scores collapse to a single staff
**Current:** parseMusicXmlStaff returns a single Staff for one partIndex (musicxml_parser.dart:parseMusicXML -> parser_support.dart:_MusicXmlImportParser.parse / _parsePartwise at parser_support.dart:1171). _parsePartwise throws if partIndex is out of range and only iterates parts[partIndex]. There is no parseMusicXmlScore that returns all parts, and within a part the <staff>N</staff> child of <note> is never read, so a piano part written on 2 staves (G+F) is flattened into one staff.
**Desired:** Expose a score-level import that returns every <score-part> as its own Staff (and ideally groups them into a Score), and split notes within a part onto separate staves by their <staff> element (MusicXML 4.0 <attributes><staves> + per-note <staff>). Piano, SATB, and any ensemble score is the single most common real-world MusicXML and currently loses all but one line.
**How:** Add a Score/multi-staff entry point alongside parseMusicXmlStaff. In _parseMeasure, key accumulators by (staff, voice) instead of voice only; read int staff = _childText(noteElement,'staff') and route. Read <attributes><staves> to size the staff count. Reuse the existing _VoiceAccumulator per (staff,voice). Keep parseMusicXmlStaff(partIndex,staffIndex) as the single-staff convenience wrapper.

## 6. [HIGH/large] (mei-import) Measure-level control events (<slur>, <tie>, <dynam>, <hairpin>, <fermata>, <dir>, <tempo>) with @startid/@endid are ignored
**Current:** _parseMeasure (parser_support.dart:1783) only iterates children of <staff>. Slur/tie are read solely as note attributes via _meiNote (@slur at parser_support.dart:2170, @tie at 2169). MEI control events that are siblings of <staff> inside <measure> — e.g. <slur startid="#n1" endid="#n5"/>, <tie startid endid/>, <dynam startid="#n1">p</dynam>, <hairpin form="cres" startid endid/>, <fermata startid/>, <dir startid/> — are never examined, and nothing resolves @startid/@endid/@plist against note xml:id.
**Desired:** Per MEI 5.0, slurs/ties/dynamics/hairpins/fermatas/directives are typically encoded as standalone control events at <measure> level referencing notes by @startid/@endid (a #-prefixed reference to a note xml:id), not as attributes on <note>. The parser should collect these, index xml:id -> imported Note/Chord, and attach SlurType.start/end, TieType.start/end, Dynamic, Ornament(fermata), MusicText/RepeatMark, and hairpin Dynamics to the referenced events.
**How:** Two-pass approach: (1) while building notes, record map<String xmlId, Note/Chord> (the model already exposes MusicalElement.xmlId). (2) After parsing <staff>, iterate the measure's other children (slur/tie/dynam/hairpin/fermata/dir) and resolve @startid/@endid (strip leading '#'). Set slur/tie type on the start and end notes; insert Dynamic/MusicText before the start note's slot; map <hairpin @form=cres/dim> to Dynamic(isHairpin:true). Fall back to @tstamp ordering when @startid is absent. This is the single biggest reason real MEI slurs/ties/dynamics import as bare notes.

## 7. [MEDIUM/small] (musicxml-import) <transpose> ignored: transposing-instrument parts import at written (wrong) pitch
**Current:** _parseMusicXmlAttributes (parser_support.dart:1337) handles only clef, key, and time. The <transpose> child (<chromatic>, <diatonic>, <octave-change>) is never read, and there is no transposition field applied to imported pitches. _musicXmlPitch (parser_support.dart:1531) takes step/alter/octave verbatim.
**Desired:** Either record the part transposition on the Staff so sounding pitch can be derived, or (commonly desired) apply it to produce concert pitch on import. A B-flat clarinet part currently imports a written C as sounding C instead of B-flat, which is wrong for playback/MIDI.
**How:** Parse <transpose> in attributes into a {chromatic, diatonic, octaveChange} record sticky across the part. Provide an option to apply it to each Pitch (shift by chromatic semitones + octaveChange octaves, respelling via diatonic) for concert-pitch import, defaulting to written pitch to preserve current behavior. MIDI mapping in lib/src/midi should consume the transposition.

## 8. [MEDIUM/small] (musicxml-export) Lyrics (syllables) are never exported despite being imported
**Current:** `_buildNoteXml` (lib/src/parsers/musicxml_parser.dart:242-301) never references `note.syllables`. The importer now parses `<lyric>` into `Note.syllables` (parser_support.dart:1303, `_parseMusicXmlLyrics`) and PROGRESS.md:250 explicitly lists 'round-trip de letras no export MusicXML' as outstanding. So lyrics import correctly but are dropped on export — round-trip loses all text.
**Desired:** For each `Syllable` in `note.syllables`, emit `<lyric number="i+1"><syllabic>single|begin|middle|end</syllabic><text>..</text></lyric>`, mapping `SyllableType` (lib/core/text.dart:36-47: single/initial/middle/terminal) to the MusicXML `syllabic` values.
**How:** Add a loop after the notations block in `_buildNoteXml`. Map initial->begin, middle->middle, terminal->end, single->single. Emit `<extend/>` for melisma/hyphen continuation if represented. Skip for chord tones (only the principal note carries lyrics).

## 9. [MEDIUM/small] (musicxml-export) Beams are never exported (auto-beam info lost on round-trip)
**Current:** `Note.beam` (lib/core/note.dart:38, BeamType) is parsed by the importer via `_musicXmlBeamType` (parser_support.dart:1296) but `_buildNoteXml` never emits a `<beam>` element. Consumers re-deriving beams from `<type>` may differ from the original beaming, and explicit beam groups are lost.
**Desired:** Emit `<beam number="1">begin|continue|end</beam>` from `Note.beam`, mapping BeamType.start->begin, BeamType.inner->continue, BeamType.end->end (inverse of the import aliases at parser_support.dart:386-388).
**How:** Add to `_buildNoteXml` after `<dot>`. A minimal version handles primary beam level 1; full fidelity for 16th+ would need secondary beam numbers, but level-1 alone restores most common cases.

## 10. [MEDIUM/small] (musicxml-export) Clef line mapping is wrong for treble/bass and missing octave clefs
**Current:** In `_buildMeasureXml` (lines 177-185) the `line` switch returns `'2'` as default for treble and `'4'` for bass, but it never sets the clef `<clef-octave-change>` and mishandles cases: e.g. `ClefType.bass` is explicitly mapped to line 4 (correct) yet `treble8vb`/`bass8va` octave variants (which `actualClefType` may resolve) lose their octave displacement. Also the `sign` derivation via `type.name.startsWith('treble')` (line 172) will classify any unexpected clef as 'C' on line 2, silently corrupting alto/percussion/TAB clefs.
**Desired:** Emit `<clef-octave-change>` for 8va/8vb/15ma variants and handle percussion ('percussion' sign) and TAB ('TAB' sign) clefs explicitly, rather than defaulting unknowns to a C-clef on line 2.
**How:** Replace the name.startsWith heuristic with an explicit ClefType->{sign,line,octaveChange} table. Emit `<clef-octave-change>-1</clef-octave-change>` for 8vb, `+1` for 8va. This is lower-frequency than tuplets/voices but a clear correctness defect.

## 11. [MEDIUM/small] (musicxml-export) Ties only emit start/stop, never tie-stop+tie-start for continuation; and <tied> notation missing
**Current:** `_buildNoteXml` (lines 264-272) emits a single `<tie>` whose type is 'stop' only when `note.tie == TieType.end`, else 'start'. A `TieType.continue`/middle note (stop AND start) gets only one tie, breaking chains of three+ tied notes. Also no `<tied>` element is emitted inside `<notations>`, which renderers (not just players) rely on for the visual slur of the tie.
**Desired:** For a continuation tie emit BOTH `<tie type="stop"/>` and `<tie type="start"/>`, and mirror them as `<tied>` elements inside `<notations>` per the spec.
**How:** Check for a 'continue'/middle TieType and emit two `<tie>` plus two `<tied>` elements. Add `<tied>` to the existing notations block. Low frequency but needed for correct multi-note ties.

## 12. [MEDIUM/small] (mei-import) Grace-note kind (<graceGrp>, @grace acc/unacc) is collapsed to a generic grace flag
**Current:** _meiNote (parser_support.dart:2173) sets isGraceNote via noteElement.getAttribute('grace') != null — it never reads the @grace VALUE (acc/unacc/unknown) nor @stem.mod (slash). Grace notes wrapped in a <graceGrp>...</graceGrp> container are not reached at all, because _parseMeiLayer has no case 'graceGrp' (the same container-skipping problem as <beam>/<tuplet>).
**Desired:** MEI 5.0 distinguishes @grace="acc" (acciaccatura, slashed) from @grace="unacc" (appoggiatura) and groups consecutive grace notes in <graceGrp>. The model already carries this distinction (Ornament acciaccatura/appoggiatura plus Note.isGraceNote). Acciaccatura vs appoggiatura affects both rendering (slash) and MIDI timing, so the kind should be preserved.
**How:** Read noteElement.getAttribute('grace'): 'acc'/'unacc' -> map to the existing acciaccatura/appoggiatura representation. Add case 'graceGrp' in _parseMeiLayer that recurses into its children marking each as grace (reuse the _appendMeiLayerChild helper introduced for the beam/tuplet fix). Without graceGrp handling, grace flourishes encoded as groups import as nothing.

## 13. [MEDIUM/small] (mei-export) MEI note/pitch attributes (@pname/@oct/@accid) have no exporter, though import conventions are fully defined
**Current:** The MEI importer `_meiNote` (parser_support.dart:2144) reads `@pname`, `@oct`, `@accid`/`@accid.ges`, `@dur`, `@dots`, `@beam`, `@artic`, `@tie`, `@slur`, `@ornam`, `@grace`. Nothing writes them. The model exposes everything needed: `Pitch.step/octave/accidentalType` (pitch.dart), `accidentalToAlter`/`accidentalToGlyph` maps, and `DurationType.meiDurValue`. The only MEI-ish writer in the repo, the MusicXML exporter's `_buildNoteXml` (musicxml_parser.dart:242), emits MusicXML `<pitch><step/><alter/><octave/>` — not MEI attributes.
**Desired:** A `_meiNote` writer emitting `<note pname="c" oct="4" dur="4" dots="1" accid="s"/>` with `@accid` derived from `Pitch.accidentalType` (s/f/n/x/ff/ss/...), `@artic` as a space-separated token list, `@tie`/`@slur` as i/m/t, `@grace` for grace notes, and `@beam` when set. Microtonal accidentals (quarterTone*, koma*, sagittal*) already in AccidentalType (pitch.dart:6) should map to MEI `@accid` values like `1qs`/`1qf`/`3qs`/`3qf` so they survive export.
**How:** Add an AccidentalType->MEI-@accid string map (the inverse of `_parseAccidentalType`). Map ClefType->(@shape,@line,@dis,@dis.place) by inverting `_meiClef` (parser_support.dart:2049): treble->shape=G line=2, bass->F line=4, alto->C line=3, etc.; octave clefs add dis=8/15 + dis.place. KeySignature->`@sig` by inverting `_meiKeySignature` (parser_support.dart:2115): `0`, `2s`, `3f`. TimeSignature->`@count`/`@unit`. Keep `Pitch.step` lowercase per MEI convention.

## 14. [MEDIUM/small] (midi-playback) TempoMark.beatUnit is ignored, so any non-quarter metronome mark plays at the wrong speed
**Current:** _consumeElement (midi_mapper.dart:328-338) emits MidiEvent.tempo(tick, bpm: element.bpm) using the raw bpm and never reads element.beatUnit (TempoMark.beatUnit, tempo.dart:9). MIDI tempo is always quarter-note based, so a notated 'half note = 60' is emitted as quarter=60 and plays at half the intended speed; 'dotted-quarter = 80' (compound meter) is similarly wrong.
**Desired:** Convert the notated beat unit to a quarter-note BPM before emitting: quarterBpm = bpm * (beatUnitInQuarters). E.g. half=60 -> quarter=120; dotted-quarter=80 -> quarter=120.
**How:** Map DurationType (+dot) to a quarter-note factor (half=2, dotted-half=3, quarter=1, dotted-quarter=1.5, eighth=0.5...) and multiply bpm by it when building MidiEvent.tempo. Apply the same conversion to the conductor's default tempo path (fromScore line 90, fromStaff line 148) and to MetronomeMark if it is ever mapped. Round to int for the SMF tempo meta.

## 15. [MEDIUM/small] (midi-playback) Fermata has no effect on playback duration
**Current:** Fermata is modelled as OrnamentType.fermata (ornament.dart:42) and imported (parser_support.dart:609 maps 'fermata'->OrnamentType.fermata), but _emitNote never inspects ornaments, so a note/rest under a fermata plays at its plain notated length. There is no hold at the final chord or at a caesura.
**Desired:** A note or rest carrying a fermata should be lengthened (commonly ~1.5x–2x its notated value, configurable). This is the single most-expected expressive timing cue, especially for the final note of a piece or phrase ending.
**How:** In _emitNote/_emitChord and the Rest branch, check note.ornaments for fermata/fermataBelow and multiply the SOUNDED duration AND the cursor advance by options.fermataScale (default ~1.75). Unlike articulations, a fermata DOES change the rhythmic advance (it extends real time), so this must adjust the returned tick count too — which then also shifts the metronome/other staves, acceptable since a fermata is a global hold. Consider only honouring it on single-voice measures to avoid per-voice desync.

## 16. [MEDIUM/medium] (musicxml-import) <divisions> ignored: durations come only from <type>, so type-less notes default to quarter
**Current:** _musicXmlDurationFromNote (parser_support.dart:1554) builds Duration solely from <type> and counts <dot> children: _parseDurationType(_childText(noteElement,'type')) ?? DurationType.quarter. The <duration> element and the measure's <attributes><divisions> are never read. Files that omit <type> (valid MusicXML, e.g. many exporters for rests or whole-measure content) silently become quarter notes, and there is no tick/onset value at all for timing.
**Desired:** Read <divisions> per measure (it is sticky across measures per MusicXML 4.0) and compute each note's real duration in divisions from <duration>; use it both to derive/cross-check the notated DurationType and to drive the backup/forward cursor and MIDI onset. When <type> is present prefer it for notation but still capture <duration> for timing.
**How:** Carry currentDivisions in _parseMeasure (default 1, updated from <attributes><divisions>). Map duration/divisions to a DurationType when <type> is absent (quarter = divisions, half = 2*divisions, etc.; handle dots via 1.5x). Store the raw division count for cursor math from the backup/forward fix.

## 17. [MEDIUM/medium] (musicxml-import) Slur/tie <number> (id) ignored, so overlapping slurs and multi-tie chords collapse
**Current:** _musicXmlSlurType (parser_support.dart:1626) iterates all <slur> under <notations> but stores only a single SlurType on the note (last one wins), discarding @number. _musicXmlTieType (parser_support.dart:1617) likewise reduces all <tie> to one TieType. Note carries a single slur and single tie field (lib/core/note.dart:40-43). Overlapping/nested slurs (number=1 and number=2 simultaneously) and chords where individual notes tie independently cannot be represented.
**Desired:** Preserve slur/tie identity (@number) so concurrent spanners survive, and attach ties at the chord-tone level for chords. At minimum, do not silently lose a second concurrent slur start/stop on the same note.
**How:** This needs a model change (list of slurs/ties with ids, or per-chord-note tie). If model change is too large now, at least detect and keep a start when both a start and stop occur on one note. For chords, _meiChord/chord merge path should carry per-note tie from <tied>.

## 18. [MEDIUM/medium] (musicxml-export) Multi-voice measures export empty (voices ignored)
**Current:** `_buildMeasureXml` only iterates `measure.elements` (lib/src/parsers/musicxml_parser.dart:155,209). Polyphonic measures are imported as `MultiVoiceMeasure`, which stores its notes in `_voicesByNumber`/`voices` (lib/core/voice.dart:179-187) and NOT in `elements`. The MusicXML importer creates these (parser_support.dart:1251-1266). On export a MultiVoiceMeasure yields only its leading system elements (clef/key/time) and zero notes for every voice.
**Desired:** For a `MultiVoiceMeasure`, emit each voice's notes with a `<voice>N</voice>` child, and insert a `<backup><duration>...</duration></backup>` between voices so they align to the same measure start, per the MusicXML partwise model.
**How:** Detect `measure is MultiVoiceMeasure`; iterate `sortedVoices`, emit voice 1's notes, then a `<backup>` of the measure's total divisions, then voice 2, etc. Also emit `<voice>` from `Note.voice` (lib/core/note.dart:56) which is currently never written even in single-voice output.

## 19. [MEDIUM/medium] (musicxml-export) Ornaments and grace notes dropped on export

**How:** Add an `_ornamentToString` switch (trill->trill-mark, mordent->mordent, turn->turn, turnInverted->inverted-turn, etc.). In `_buildNoteXml`, if `note.isGraceNote` emit `<grace/>` and skip `<duration>`. Fold ornaments into the existing `<notations>` block alongside articulations.

## 20. [MEDIUM/medium] (musicxml-export) Barlines and repeats (RepeatMark, barline/repeat barlines) not exported

## 21. [MEDIUM/medium] (mei-export) No MEI serializer exists at all — MEI is import-only despite a "100% MEI v5" claim
**Current:** There is zero MEI write path. `MEIParser` (lib/src/parsers/mei_parser.dart) only exposes `parseMEI`, an 8-line wrapper delegating to `parseMeiStaff` (lib/src/parsers/parser_support.dart:73). A repo-wide grep for `toMei`/`MeiExport`/`writeMei`/`serializeMei`/`staffToMEI` returns 0 hits. By contrast the MusicXML side is symmetric: `MusicXMLParser.staffToMusicXML` (lib/src/parsers/musicxml_parser.dart:14) and `mergeStaffs` (musicxml_parser.dart:100) emit `<score-partwise>` v4.0. CHANGELOG.md:88 advertises 'MEI v5 100% conformance' and CHANGELOG.md:98 lists `DurationType.meiDurValue`/`fromMeiValue` 'for MEI serialization', yet those helpers are never called anywhere — there is no consumer of the write path. PROGRESS.md H1 already flags the 100% claim as an overclaim for import (~30%) and rendering (CMN-only) but does not even mention export, because none exists.
**Desired:** A public `MEIParser.staffToMEI(Staff)` (and `scoreToMEI(Score)` for multi-staff) that produces a well-formed MEI 5 document: `<mei><meiHead/><music><body><mdiv><score><scoreDef/><section>` then per-measure `<measure n><staff n><layer n>` with `<note>/<rest>/<chord>` children. This makes the advertised round-trip real and lets the existing MEI importer re-read its own output.
**How:** Mirror staffToMusicXML's XmlBuilder structure. Reuse helpers that already exist and are currently dead: `DurationType.meiDurValue` (duration.dart:77) for `@dur`, `note.duration.dots` for `@dots`, `pitch.step.toLowerCase()` for `@pname`, `pitch.octave` for `@oct`.
